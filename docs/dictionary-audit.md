# فرهنگ‌لغت — dictionary catalog audit

**Status:** measurement complete. Nothing here is implemented. `LEG-013`.

**Source of truth:** `data/words.json`, 10,524 entries, verified byte-identical to the `VOCAB_WORDS` asset inside `english-vocab-v1.html`. `node tools/validate.js` → `ok — 10524 entries valid`, **0 errors and 0 warnings**. Every finding below is invisible to the current validator.

**Scope.** This audits the catalog **as a dictionary / search corpus**. It is no longer the teaching sequence — `LEG-012` rebuilt that from an external CEFR-graded source (`data/curriculum.json`). Two constraints from the product owner shape every recommendation: **nothing is deleted**, and the catalog **will be grown substantially** later.

Cross-references used: `/usr/share/dict/web2` (Webster's 2nd, 235,976 headwords) and `/usr/share/dict/propernames` (1,308 given names).

---

## 0. The structural fact that explains almost everything else

The catalog is **two datasets joined at index 2119**, and essentially all the damage is on one side of the seam.

```
2114-2124:  gateway, Data, arrival, radar, dada, │ the, and, for, that, this, with
                                                 └── seam
```

| index block | multiword entries per 500 | character |
|---|---|---|
| 0–2118 | 51 | hand-authored curriculum — phrases, collocations, coherent topic blocks (history/archaeology 1943–2111, nutrition 1590–1730) |
| 2119–10523 | 7 → **0** | raw web-corpus unigram frequency descent |

**8,405 entries (79.9% of the catalog) are an unfiltered frequency dump.** Every category below is a symptom of that one decision. The exact upstream list could not be identified offline; the composition (porn-site domains, protocol acronyms, US given names and city names, German/French function words, all in descending frequency) is consistent with a public web-crawl unigram list — treat the specific attribution as unverified.

**The corollary is good news:** the first 2,119 entries are broadly sound, the curriculum is now sourced externally anyway, and flagging the frequency dump rather than deleting it costs one file and one bundle asset.

### F2 — 8,685 example sentences are template fills; 1,513 are ungrammatical English

The `ex` field was generated by dropping the headword into a fixed frame with no regard for part of speech or number.

**1,857 distinct templates; the top 5 cover 6,809 entries, the top 20 cover 8,685 (82.5%).** Only 1,839 entries have a bespoke example.

| n | template | entries |
|---|---|---|
| 1 | `do you remember that ~?` | 1,379 |
| 2 | `i need a new ~ for my work.` | 1,376 |
| 3 | `we talked about the ~ for an hour.` | 1,358 |
| 4 | `this ~ is very important to me.` | 1,351 |
| 5 | `the ~ changed everything for us.` | 1,345 |
| 6 | `the weather was very ~ yesterday.` | 241 |

> **This corrects `docs/feature-map.md` M5**, which reports 36 templates covering 10,508 of 10,524. That is stale — a later `examples` agent pass rewrote 1,839 examples, concentrated at low indices. Current figure: 1,857 templates / 8,685 covered.

**Grammar breakage, measured two ways:**

1. **Plural or 3sg headword in a singular-determiner frame — 1,513 entries.** `This authorities is very important to me.` (35) · `I need a new colleagues for my work.` (106) · `Do you remember that pounds?` (5248).
2. **Category/frame POS mismatch — 666 entries.** 244 `adj` in a noun frame (`I need a new disgusting for my work.`), 270 `verb` in a noun frame (`I need a new enhance for my work.`), 41 `adv` in a noun frame (`I need a new not for my work.`), 111 `noun` in an adj/verb frame (`Learning to pushed takes time and practice.`). This undercounts badly — 4,599 entries carry the topical `cat: "noun"` regardless of actual POS.

**Impact.** The `cloze` mode and the writing drill blank the headword out of this same sentence, so the learner is asked to reconstruct sentences that are not English — and 1,513 actively model a determiner–number agreement error, precisely the error Persian speakers make most.

**Fix cost.** Large. 8,685 sentences need regeneration with real POS data.

### F3 — 773 Persian example translations are nonsense

`exfa` is a Persian frame with the `fa` gloss dropped in. **7,457** `exfa` values match one of nine Persian frames. Of the noun-slot ones, **456** are filled with a Persian verb form and **319** with a proper-name/abbreviation metadata label — **773 entries** where the Persian is ungrammatical or meaningless.

- 9627 `leon` — `یک ساعت درباره‌ی نام خاص حرف زدیم.` ("we talked about the proper noun for an hour")
- 9456 `yemen` — `برای کارم یک کشور عربی تازه لازم دارم.` ("I need a new Arab country for my work")
- 176 `download` — `برای کارم یک دانلود کردن تازه لازم دارم.` (verb infinitive in a countable-noun slot)
- 6329 `sought` — `آن جست‌وجو کرد همه چیز را برای ما عوض کرد.`
- 6644 `fucked` — `(غیرمناسب) خراب کرد زمان و تمرین می‌خواهد.` — the warning label is *inside* the rendered sentence

**Impact.** The Persian side is the learner's anchor. When it reads "we talked about the proper noun for an hour," the learner is being shown the generator's internals.

**Fix cost.** Large, strictly downstream of F2.

### F4 — 836 proper nouns; 41.7% of `people` and 30.5% of `place`

| rule | hits | precision |
|---|---|---|
| P1 — `fa` matches a proper-name label | 398 | ~98% (1 FP in 45 sampled) |
| P2 — headword ∈ `/usr/share/dict/propernames` | 408 | ~66% (14 FP in 41) |

> `docs/placement-test-methodology.md` P8 reports 326 for the gloss rule; the regex here is wider (adds `نام‌سایت`, `(نام …`, `نام شاعر`, `نام هتل`, `اسم خاص`) and lands at 398. Both are correct for their own regex.

The **114-way** gloss collision on the bare string `نام خاص` is the largest duplicate in the catalog: `kelly, austin, toronto, missouri, andrew, joseph, philadelphia, lewis, howard, sam, allen, jennifer, …`. `نام خانوادگی` collides 23 ways, `نام زنانه` 9, `نام شهر` 6.

| cat | total | flagged | % |
|---|---|---|---|
| `people` | 422 | 176 | **41.7%** |
| `place` | 429 | 131 | **30.5%** |
| `time` | 158 | 20 | 12.7% |
| `noun` | 4,599 | 440 | 9.6% |

**Impact.** `buildOptions()` tier 4 draws distractors from the same `cat`. In a `people` question, ~2 in 5 candidates are names glossed `نام خاص`. The `takenShown` guard prevents two identical labels, so the typical corrupted question is `{خانواده, دوست, نام خاص, مدرسه}` — trivially answerable by elimination. **Junk distractors do not make the drill harder; they make it falsely easy**, so the SRS records successes the learner did not earn and schedules the word further out.

### F5 — 2,911 entries are inflections of another headword already present

| suffix | entries | example |
|---|---|---|
| `-s` | 1,631 | 2716 `topics` ← 2715 `topic` |
| `-ed` | 470 | 4658 `opened` ← `open` |
| `-ing` | 462 | 7488 `expanding` ← `expand` |
| `-er` | 184 | 8026 `headers` ← `header` |
| `-ly` | 141 | 6886 `naturally` ← `natural` |
| `-est` | 23 | 7818 `hottest` ← `hot` |

Precision ~87% (30 sampled, 4 false — all because the *base* was itself a junk 3-letter entry). Restricting to `-s`/`-ed`/`-ing` (2,563) removes the arguable cases; `-ly` adverbs are legitimate independent headwords.

### F6 — 1,244 entries share a Persian gloss; 949 collide inside one category

- **499** glosses shared by >1 entry, covering **1,244** entries.
- **949** entries share an identical gloss with another entry **in the same category**.
- **5,947 entries (56.5%)** have a *near*-duplicate gloss in the same category under the app's own `faNear` containment rule.
- **5 headwords are outright duplicated:** `subject` (1205/10003), `women` (2300/5105), `children` (2355/8046), `film` (2586/9623), `bestiality` (5142/5361/10376).

Legitimate synonym collisions (`choose/select/elect` → `انتخاب کردن`) are mixed with pure junk (114× `نام خاص`).

**Impact.** The distractor filter must reject a majority of same-category candidates (56.5% near-collide), so tier 4 frequently runs dry and falls through to tier 5 random-over-catalog — **exactly the behaviour `LEG-005` was written to eliminate. The junk is quietly defeating the fix.**

### F7 — ~200 acronyms and brand names; the obvious rule is unusable

`scsi`, `pentium`, `cingular`, `tripadvisor`, `expedia`, `nasdaq`, `gpl`, `irc`, `rfc`, `isp`, `ssl`, `seo`, `gsm`, `jelsoft`, `macromedia`, `kelkoo`, `suse` are entries.

### F12 — ZWNJ inconsistency (reported, but the rule cannot say which side is wrong)

64 entries write a compound **without** the ZWNJ the same corpus writes **with** it elsewhere (`سازماندهی` vs `سازمان‌دهی`). **This is not a defect detector**: for `تنها`, `بیشتر` and `کتابخانه` the ZWNJ-free spelling is correct and the ZWNJ-bearing occurrences elsewhere are the errors. ## 2. Two things that are *not* broken

- **The placement test no longer draws from this catalog.** `PLACEMENT_WORDS` is seeded from the curated `data/placement.json` ("no proper nouns"). The failure documented in `docs/placement-test-methodology.md` §2.4 — where C2 asked `ampland` — is fixed. The catalog no longer decides anyone's level.

**P1 regex, verbatim** (note `\s+`, not `\s*` — with `\s*` it wrongly catches `نامشخص`):

```js
/(^|[\s(\/،«])(نام|اسم)\s+(خاص|زن|زنانه|مرد|مردانه|شخص|شخصی|خانوادگی|کوچک|شهر|کشور|مکان|سایت|برند|تجاری|شرکت|انگلیسی|مستعار|فامیل|انسان|محل|ایالت|شاعر|رودخانه|هتل)|نام‌سایت|\(نام\)|\(نام\s/
```

**What no rule here can do.** None detects a *wrong translation of a real word*. `hello → سالم` passes every rule above. Gloss correctness needs a Persian reference lexicon (not in this repo) or human review. **Any plan that assumes a regex will find it is wrong.**

## 4. Recommendation: an index-keyed flag file, folded into the bundle as a parallel asset

> **Create `data/word-flags.json`, keyed by word index, holding short reason codes. Teach `tools/rebuild.js` to emit it as a parallel `VOCAB_FLAGS` array alongside `VOCAB_WORDS`. The app consumes it to filter the *teaching* order, the *distractor* pool and the *game* pool — and never the search index.**

### Why not a per-entry field

Adding `kind` to `FIELDS` in `tools/validate.js` is a one-line change, so cost is not the objection. Three real objections are:

1. **`tools/ingest.js` carries its own independent `FIELDS` list.** A new per-entry field would have to be added there too, or every bulk-appended entry arrives silently unflagged — precisely the failure mode that created this mess. Two field lists in two files that must stay in sync is a latent bug.
2. **`data/patches/*.json` are index-keyed field merges.** A quality judgement expressed as a word field is indistinguishable, in a patch, from a content edit — so an `examples` agent and a quality reviewer can clobber each other.
3. **Editorial judgement about an entry is not a property *of* the entry.** Putting it there makes every future `git diff` of `words.json` a mix of content and policy.

### Why not category reassignment

Moving proper nouns to a `propn` category is cheap and would immediately clean the `people` (41.7%) and `place` (30.5%) distractor pools. But `cat` is **single-valued, topical, user-visible, and learner-overridable** (`vocab_catover`). It cannot express two facts at once: `milfhunter` is a proper noun *and* obscene; `bestiality` is genuinely `crime` *and* unteachable. Overloading `cat` destroys the topic information, which is the one thing it is for. **Reject as the primary mechanism** — a flag file cleans the same pools without the loss.

### Why not a passive exclusion list

A `data/exclusions.json` that nothing reads is documentation, not a fix. If the goal is "the learner stops seeing `blowjob`", the flags must reach the runtime, and the only path there is `rebuild.js` writing a bundle asset.

### Shape

```json
{ "5111": ["explicit","brand"],
  "4078": ["propn"],
  "3756": ["inflection:3755","explicit"],
  "9155": ["nonword"],
  "2113": ["morpheme"] }
```

Codes, each mapping to a rule in §3: `explicit` (X1) · `propn` (P1∪P2∪P3) · `brand` (manual + ACR2) · `acronym` (ACR2) · `nonword` (N1 after triage) · `morpheme` (M1) · `foreign` (F1) · `unglossed` (U1) · `inflection:<base>` (D1) · `dupe:<canonical>` (G1) · `badexample` (W1/W2) · `badgloss` (manual).

### Why this satisfies both constraints exactly

- **Nothing is deleted.** `words.json` untouched, `i` frozen, `en` frozen, `tools/prune.js` never run. Dictionary search reads `this.W` directly and keeps returning all 10,524. Someone looking up `bestiality` still finds it — it just stops being *dealt as a lesson*.
- **Growth is cheap.** A 20,000-entry expansion appends to `words.json` and appends to `word-flags.json`. Neither file is rewritten. Index-keying inherits the frozen identifier the rest of the pipeline already relies on.

**Bundle cost:** ~120 KB uncompressed, well under 20 KB gzipped, against a 6.1 MB bundle.

**One thing to get right:** `tools/ingest.js` extends `VOCAB_ORDER` with every newly appended index. Either `ingest.js` must stop auto-appending to the teaching order, or the app must filter `VOCAB_ORDER` through the flags at load. **The second is safer** — it makes the flag authoritative regardless of who wrote the order.

## 5. Growing the catalog: what to feed `ingest.js`, and the gate in front of it

`tools/ingest.js` is sound — enrich-never-replace and append-never-insert are the right invariants and are enforced rather than trusted. Three things a bulk expansion must plan around:

1. **It silently drops any new entry lacking `fa`, `ex` *and* `exfa`.** A bulk source with definitions but no examples will enrich existing headwords and add **zero** new ones, reporting them all as `skipped`.
2. **It defaults `cat` to `'general'`.** A 20,000-entry import with no category mapping destroys the browse screen.
3. `problems` is declared and printed but never written to — dead code. Harmless; worth knowing before trusting its output.

**What to feed it.** Not another frequency list — frequency is what produced `ampland`. Feed it a **lemmatised, POS-tagged, CEFR-or-band-graded lexicon** where every row carries: lemma (not inflection), POS, one sense per row, a Persian gloss under 60 characters (the validator's hard limit), and an example that actually contains the lemma and is grammatical for that POS. **The correct first import is not an expansion at all** — it is the ~35 missing basics from F8, plus the lemmas whose inflections are already present (`sock`, `glove`, and the ~1,600 bases implied by D1), plus the 4,305 pending-content entries `LEG-012` already enumerated.

**The gate.** A `tools/gate.js` that runs *before* `ingest.js` and rejects the **file**, not individual rows, if any threshold trips. Every check already exists as a measured rule in §3, so this is assembly, not research:

| check | rule | threshold |
|---|---|---|
| obscenity / porn-domain | X1 | **0 permitted — hard reject** |
| proper-name gloss label | P1 | 0 |
| given-name / cap-only gazetteer | P2 ∪ P3 | flag for review, ≤1% |
| acronym-shaped with expansion gloss | ACR2 | ≤0.5% |
| self-admitted `نامشخص` gloss | U1 | 0 |
| bound morpheme / single letter | M1 | 0 |
| foreign function word | F1 | 0 |
| headword is an inflection of an existing headword | D1 | 0 — enrich the lemma instead |
| example matches a known template | W1 | **0** |
| plural headword in singular frame | W2 | 0 |
| gloss collides exactly within same `cat` | G2 | ≤0.5%, listed |
| gloss >60 chars | `validate.js` | 0 |
| `cat` present and ∈ `CATS` | `ingest.js` | 100% required |

Plus one rule that matters more than all of them: **every imported row must record its source and licence** — the current catalog's provenance is unknown, and that is why nobody can tell which of the 10,524 entries were ever reviewed.

**Run the same gate over the existing catalog once and store the output as the initial `data/word-flags.json`.** That is the cheapest path from "we know it's dirty" to "we know exactly which 3,000 entries are dirty and why."
